\## 一、核心疑问：这个品类为什么别人不做？

## 4\. 各数据源采集器实现规范

### 4.1 ChatGPT 采集器

**输入**：用户从 ChatGPT 设置中导出的 ZIP 文件（包含 `conversations.json`）。  
**输出**：`List[MemoryItem]`，包含每条用户消息和AI回复。

**实现文件**：`src/collectors/chatgpt.py`

**核心逻辑**：

1.  解压 ZIP，读取 `conversations.json`
    
2.  遍历每个 conversation，提取 `messages` 数组
    
3.  对每条消息，生成 MemoryItem：
    
    *   `type` = "conversation"
        
    *   `content` = 角色 + 内容（例如 "用户: xxx" 或 "AI: xxx"）
        
    *   `metadata` 包含 `conversation_id`, `role`, `message_index`, `model`（如果存在）
        
4.  去重：基于 `conversation_id` + `message_index` 计算 hash
    

**异常处理**：如果文件不存在或 JSON 格式错误，打印错误并跳过。

**CLI 集成**：

### 4.2 Cursor IDE 采集器

**数据位置**：

*   macOS: `~/Library/Application Support/Cursor/User/workspaceStorage/.../state.vscdb`
    
*   更简单的方法：Cursor 将聊天历史存储在 SQLite 中，通常位于 `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb`（需要确认具体表名）。
    

**替代方案**（更稳定）：  
Cursor 是 VS Code 的分支，聊天记录可能存储在 `~/.cursor/` 下的 SQLite。建议采用**社区已知路径**：  
`~/.cursor/User/History/` 或通过读取 `~/.cursor/User/globalStorage/state.vscdb` 中的 `com.todesktop.230113mceditor.plugins.chat` 表。

**为保证可实施性，本报告提供一种简单方案**：  
用户需手动导出 Cursor 聊天记录（Cursor 目前无官方导出），但我们可以读取其本地 SQLite。  
**具体步骤**：

1.  扫描 `~/.cursor/User/workspaceStorage/*/state.vscdb`，查找包含 `chat-history` 的表。
    
2.  使用 `sqlite3` 连接，执行 `SELECT value FROM ItemTable WHERE key LIKE '%chat%'`。
    
3.  解析 JSON 值，提取对话。
    

**如果路径不确定，采集器应报错并提示用户手动提供文件**。  
**输出**：每条对话消息作为 MemoryItem，`source="cursor"`。

### 4.3 Claude Code 采集器

**数据位置**：  
`~/.claude/projects/` 目录下，每个项目一个子目录，内有 `agent-state.jsonl` 或 `conversations.jsonl`。  
文件格式：每行一个 JSON 对象，包含 `role`, `content`, `timestamp` 等。

**实现**：

1.  遍历 `~/.claude/projects/*/*.jsonl`
    
2.  逐行解析，提取 `role`, `content`, `timestamp`
    
3.  生成 MemoryItem，`source="claude-code"`
    

**注意**：Claude Code 的 JSONL 可能包含工具调用和系统消息，过滤只保留 `user` 和 `assistant` 角色。

## 问题一：Cursor 采集器方案是“幻想”，没有验证

报告里写：“Cursor 是 VS Code 的分支，聊天记录可能存储在 … 建议采用社区已知路径 … 或通过读取 … state.vscdb 中的表”。

**锐评**：

*   你根本没有实际打开过 Cursor 的本地数据库。Cursor 的历史记录**不在** `state.vscdb` 的常规表里。它把聊天记录存在 `~/.cursor/` 下的 SQLite 文件，但字段名、编码方式、甚至存储位置在不同版本之间都变过。
    
*   报告里说“自动搜索 `~/Library/Application Support/Cursor/` 下的 .db 文件” —— 这会搜出一堆无关数据库，然后你解析哪个表？哪个字段？没有给出任何确定的 schema。
    

**后果**：开发人员会花 2 天时间到处找，最后发现要么做不到，要么只能支持某个旧版本。**Cursor 采集器在当前阶段根本不成熟，不应该放进 MVP。**

**修正建议**：

*   砍掉 Cursor 采集器，用 **VS Code 的 Copilot Chat 导出** 替代（有社区工具 `copilot-chat-export`）。
    
*   或者**只支持 ChatGPT + Claude Code**，把 Cursor 推迟到 Phase 1。
    
*   如果非要做，先手动在自己的 Cursor 里找到真实的 `chat_history` 表结构，把 SQL 语句硬编码进去，不要用“自动搜索”。
    

* * *

## 问题二：Claude Code 的 JSONL 解析过于简单

报告里写：“文件格式：每行一个 JSON 对象，包含 role, content, timestamp”。

**锐评**：

*   Claude Code 的 JSONL **不是** 统一格式。有的版本是 `{"role":"user","content":[...]}`，有的版本把内容包在 `parts` 数组里，还有的包含 `tool_use` 结构。你只假设 `role` 和 `content` 字段，会漏掉大量消息，甚至解析失败。
    
*   也没有处理多模态（图片、文件）和工具调用的嵌套结构。
    

**后果**：导入后你会发现只能拿到一半对话，而且时间戳错位。

**修正建议**：

*   增加一个“宽松解析模式”：先尝试直接取 `content`，如果没有则递归提取所有 text。
    
*   明确只支持 Claude Code 的**最新版本**（例如 v1.0.15 以上），在文档里注明版本要求。
    
*   提供一个 `--validate` 选项，抽样检查前 10 行，报告成功解析的比例。

## 问题三：SQLite 存储缺少“原始信息”和“元数据扩展性”

报告里的 `memories` 表只有 `content`（文本）和 `metadata_json`。看起来够用，但实际不够。

**锐评**：

*   你想后续做“推理式记忆”（例如从对话中总结偏好），那么每条消息不仅要存文本，还要存**父对话 ID**、**消息顺序**、**编辑历史**。当前 schema 没有这些关系字段，后期要改表结构。
    
*   `metadata_json` 是 JSON 字符串，但 SQLite 对 JSON 查询支持很弱（需要安装扩展）。如果你未来想查询“metadata 里 model 是 gpt-4 的消息”，会非常痛苦。
    

**后果**：数据导入后，你想做“情感分析”或“风格提取”，发现无法把多条消息串成一个对话线程。

**修正建议**：

*   增加 `conversation_id` 字段（字符串）和 `parent_id`（指向上一条消息）。
    
*   增加 `message_index`（整数）字段，不塞进 metadata。
    
*   把常见元数据（model, role, character\_count）做成独立列，只把不固定的内容放 metadata。
    

* * *

## 问题四：执行计划过于理想，低估了环境差异

报告里说 M1 到 M5 总共 7 天。  
**锐评**：

*   光是让 ChatGPT 导出解析做到“提取偏好、写作风格”就远不止 2 天。因为你要从非结构化的对话中推断“用户纠正AI”这种信号，需要编写规则或小模型。报告里完全没有给出具体算法。
    
*   “增量导入基于文件 hash”听起来简单，但 ChatGPT 导出 zip 里可能有多个文件，你要计算整个 zip 的 hash，还是单个 conversation 的 hash？没说清楚。
    
*   没有考虑**重复导入同一数据源但不同时间点**的情况——用户可能今天导入，下周又导出一次新对话。你需要合并而不是覆盖。
    

**后果**：7 天后肯定交不出可用的 CLI。至少要 2 周。

**修正建议**：

*   将 Phase 0 拆成两个里程碑：
    
    *   **P0.1 (1 周)**：只支持 ChatGPT 导出，只做“提取原始消息并存储”，不做偏好推理。
        
    *   **P0.2 (1 周)**：支持 Claude Code，加上增量更新逻辑。
        
*   把“推理偏好”移到 Phase 1（记忆检索时再做）。
