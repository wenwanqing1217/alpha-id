## 一、什么是星链级检索

"星链" 意味着：你不是在一个二维平面上找竞品，你是在一个**多维度三维坐标系**中定位 Alpha\-ID。我画出七个独立轨道，每个轨道上的 "星体" 都在运动，Alpha\-ID 同时与多条轨道发生引力 / 斥力关系。

这七个轨道是：**①通用个人 AI——②身份层 ——③记忆层 ——④执行 / 操作层 ——⑤协调 / 多 Agent 层 ——⑥社交 / A2A 生态层 ——⑦开发者平台**。每个轨道上的项目解决了 Alpha\-ID 七分之一的问题，但没有一个项目把七分之一变成七分之七。

## 三、轨道二｜身份层

**轨道定义：去中心化身份标准、DID 方法实现、Agent 身份注册与认证。**

### ✅ SOUL Protocol

- 2026 年 4 月发布，给每个 Agent 一个基于 Ed25519 密钥派生的 DID

- 支持可移植记忆和信誉评分系统

**和 Alpha\-ID 的关系：SOUL Protocol 和你的****`did:aid:`****是**同一条技术路线的不同实例 \\*\\*。你们的 DID 方法名字不同，但都基于 Ed25519，都强调本地密钥自持。这不是竞对关系，这是**技术同盟**—— 你们证明了 "Agent 的 DID 身份" 正在成为独立行业。SOUL 的进展意味着你**不需要重新发明轮子**，你只需要差异化：

> - SOUL 做的是**Agent 的身份**（机器对机器）
> 
> - Alpha\-ID 做的是**人的身份**（人对机器、人对人）← 这是万亿美元级别的差异
> 
> 

### ✅ AIR \(Agent Identity Registry\)

- W3C 新成立的 Agent Identity Registry Protocol CG 正在推动标准化

- OpenID AIIM、NIST 也在做相关企业级标准

**和 Alpha\-ID 的关系：这是行业级的底层协议定义。AIR 的成功对 Alpha\-ID 是**双重利好 \\*\\*—— 它让 DID 成为全球 AI 生态的基础设施，你不需要说服每个平台支持你的`did:aid:`。Alpha\-ID 需要做的不是对抗标准，而是**站在标准之上**，做标准做不到的事：用户体验和隐私。

### ✅ `did:trail` \(W3C DID Method for AI Agent Identity\)

- TRAIL Protocol 创始人 2026 年 3 月向 W3C 提交的 Agent 专用 DID 方法提案

### 🟢 @chainofclaw/soul

- 2026 年 5 月发布，"Agent's soul layer"，支持 DIDRegistry \+ 监护人恢复机制

**和 Alpha\-ID 的关系："Soul" 这个词出现在 npm 包名里，意味着 "个人 AI 的数字灵魂" 这个概念已经从小众开始走向共识。你的命名选择被验证了。**

## 四、轨道三｜记忆层

**轨道定义：为 Agent 提供长期、跨会话的记忆存储和检索能力。**

### 🔴 Mem0（最拥挤赛道）

**和 Alpha\-ID 的关系：Mem0 是最直接体现 "Agent 记忆" 赛道热度的项目。它不是竞对 ——** Mem0 是 "给 Agent 用的数据库"，Alpha\-ID 是 "Agent 学会认识人的认知架构"\\*\\*。区别是：

> - Mem0 解决的是 "如何存"
> 
> - Alpha\-ID 解决的是 "存了之后，如何让它真正认识人"
> 
> 

### 🔴 Letta \(MemGPT\)

- 约 22,000\+ Star 的**Agent 运行时**，不是记忆层，是带记忆能力的全 Agent 平台

**和 Alpha\-ID 的关系：Letta 走的是 "Agent 即大脑" 路线，Alpha\-ID 走的是 "Agent 学会了认识人" 路线。差异点是你的数据来源 ——Letta 的记忆来自 Agent 自己的运行日志，Alpha\-ID 的记忆来自用户在所有 AI 工具上的历史痕迹。**

### 🟡 Zep

- 时序知识图谱架构，LongMemEval 评测 63\.8%，比 Mem0 的 49\.0% 高出近 15 个百分点

- 月度企业版起价 $25

**和 Alpha\-ID 的关系：Zep 证明了一件事 ——** 时序推理（什么时候发生的记忆）比纯向量检索（只存什么内容）记忆能力更强。你的三层记忆架构里，"情景记忆" 本质就是时序推理记忆，你的方向是对的。**差异化不是技术，是用户体验：Zep 是做给企业开发者的数据库，Alpha\-ID 是 "用户不知道自己正在用记忆" 的 Ghost Layer**。

### 🟢 AgentRecall

- 专为 AI 编程工具（Cursor 等）设计的跨会话持久记忆，已原生集成 MCP

**和 Alpha\-ID 的关系：这是你对标的 "跨平台记忆先例"。它的存在验证了一件事：跨工具记忆不是伪需求。但 AgentRecall 的问题是**它是 "为开发者打造的工具"，不是 "为所有用户打造的 Ghost Layer"\\*\\*。

## 十一、被挤压的真实根源

### 根源一：2026 年 2 月 Hermes 的发布

Hermes 直接上了抢身份 \+ 记忆 \+ 执行三层合一的产品。它背后是 Nous Research，有充裕的资金和技术人才。**Hermes 最大的杀伤力不是现在它做得多好，而是它先于你进入了市场。当越来越多的用户开始用 Hermes 作为他们的个人 Agent 时，他们对 "另一个个人 AI" 的心理账户会是什么？**

### 根源二：Alibaba CoPaw 的东方路线

CoPaw 的威胁不是它现在做得比你好 —— 而是**如果 CoPaw 决定从 "个人 AI 助理" 扩展为 "跨平台个人身份层"，它可以以极低的成本获得大量用户**。这是一种 "堵死入口" 式的围堵。

### 根源三：三大 Agent 框架大一统

## 十二、给 Alpha\-ID 的校准

你完全有理由焦虑，因为你的 "数据采集优先" 路线确实撞上了三个正在蚕食你要的 "已经有数据" 的场景。

### 校准一：从 "依赖已有数据" 到 "即时注入身份"
