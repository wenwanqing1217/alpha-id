# Alpha-ID 全方位规划书

> 这不是 6 家 AI 发言的合集。
> 这是我读完所有东西之后，站在自己中心点做出的判断和规划。

---

## 一、中心判断

Alpha-ID 的核心（DID + 三层记忆 + TwinBrain + 803 测试）已经足够硬了。它当前最大的问题根本不是能力不够，是**从"能跑"到"有人用"之间的那一公里没走通。**

你不需要再叠任何新功能。你需要的是让第一个用户在 3 分钟内跑通 `aid collect → aid profile show` 然后说一句"有点东西"。

这个中心判断决定了后面所有决策：一切不为这个目标服务的东西，都是噪音。

---

## 二、第一跳：用户是谁

你的产品最终面向所有人（Ghost Layer 不需要学习成本），但 P0 必须先选一个群体打透。

**我的判断：P0 打开发者，但入口不做死。**

开发者群体你不需要教他们用终端、不需要解释 DID、不需要做 GUI。`pip install alpha-id` + `aid collect` 他们自己就会。

但入口不做死的意思是：不把 CLI 当唯一通道。
- 有 ChatGPT 导出数据的走导入
- 没有导出数据但愿意聊几句的走 3 个问题
- 两个都不想、就想看一眼长什么样的，仓库里放一个样本 ZIP，`aid collect sample` 一键体验

这不是"选 CLI 还是 Web"，是"三种人都能进来"。

---

## 三、第二跳：P0 做什么

**唯一目标：看到画像，说"有了"。**

```
aid init                → 目录就绪
aid collect chatgpt     → 解析 ZIP → 提取 → 保存
aid profile show        → 看到文本画像
```

**P0 不做的事（一件都不做）：**
- ❌ MCP 注入（用户还不知道你是谁，注入到哪里去？）
- ❌ HTML 粒子星链（看了觉得酷，然后呢？）
- ❌ Safety Layer（还没有人操作，保护什么？）
- ❌ A2A 协议（一个用户都没有，跟谁通信？）
- ❌ 语音交互（话都不会说，先走稳）
- ❌ Cursor/Claude 采集器（一个源都没跑通，加源干什么？）
- ❌ export_card() 分享图（拿什么分享？一张文本截图？）

**P0 做完的状态：**
- ~500 行新代码
- 812 个测试全绿
- 一个人用 pip 安装后 3 分钟内看到自己的对话画像
- 画像底部写一行："下个月：打开 Claude，它认识你"

---

## 四、第三跳：P1 的优先级（等 P0 发了再定）

P1 做什么不取决于我们现在的规划，取决于 P0 发布后真实用户的反馈。

但预埋的方向是：
1. MCP 注入（魔法时刻：回 Claude 发现它认识你）
2. Web 端粒子星链（视觉差异化）
3. export_card() 病毒传播（"ChatGPT 突然认识我了"）
4. Safety Layer 最小 3 条规则

**为什么现在不定死？**  
宇宙星链的原则是第一节点跑通后再决定第二节点。P0 跑通之前不规划 P1 的细节。
