## 一、项目核心定位

### 1.1 一句话定义

**把散落在数字世界里的你捡起来——收集、重组、延续，让它替你活着、替你社交、替你学习。**

### 1.2 它不是什么

Alpha-ID 不是：
- "身份认证工具"
- "记住密码"
- "跨平台登录"

Alpha-ID 是：**你在所有 AI 工具间的数字存在连续性**

### 1.3 核心价值主张

你同时在用 Web ChatGPT、Codex、Cursor、Hermes、Harness——每个平台都只认识你的一个碎片。你不应该在不同工具里活成不同的人。

Alpha-ID 做的事：
- **收集**：你在各处的数字足迹（对话、代码、偏好、习惯）
- **统一**：成一个完整的、属于你的数字存在
- **注入**：回你使用的每一个 AI 工具——让它们都认识同一个你

### 1.4 终局画面

五年后，一个开发者打开他的电脑：

```
ChatGPT 在聊需求 → 知道他的思考方式
Codex 在写核心逻辑 → 知道他的代码风格和项目上下文
Hermes 在跑自动化 → 延续他上次调通的参数和偏好
Harness 在部署 → 知道他的环境配置习惯

所有这些工具底下的"那个开发者"是同一个完整的他。
```

他新装了一个 AI 工具，第一次打开——那个工具已经知道他。不是因为他在设置里填了资料，是因为他的 Alpha-ID 已经在了。

## 二、战略宣言

### 2.1 使命

**你的数字存在是连续的。不管你在哪个平台上。**

### 2.2 核心洞察

大厂做的事：让你习惯"不存在"。

| 平台 | 他们让你习惯什么 | 你失去什么 |
|:-----|:---------------|:-----------|
| ChatGPT | 我的记忆存在 OpenAI 服务器里 | 数据主权意识 |
| Claude | Projects 帮我管理上下文 | 跨平台连续性需求 |
| Cursor | Composer 记住我的代码风格 | 风格可迁移的认知 |
| 浏览器 | 书签同步到云端 | 数字足迹属于自己 |

Alpha-ID 的使命：**让用户第一次意识到，这些数据本来就该是我的。**

### 2.3 三条路径，一条优先

| 层 | 做什么 | 优先级 |
|:--:|-------|:------:|
| **第一层：记忆** | 把你散在各处的数字足迹收拢、统一 | **P0 — 现在** |
| **第二层：桥接** | 让你进入任何 AI 工具时，它自动知道你 | **P1 — 确认记忆能收之后** |
| **第三层：操作** | 你发一个指令，它替你执行 | **P2 — 有用户基数后** |

### 2.4 MVP 的魔法时刻

> 用户把自己的 ChatGPT 导出拖进一个工具。5 秒后他看到一张卡片：
>
> "我从你 47 段对话中了解到：你凌晨活跃，擅长 Python/React，写作偏好短句，最近在关注 MCP 和 AI Agent。你在所有 AI 工具中的同一个你，从现在开始存在了。"

这个体验不需要 MCP 配置、不需要改 JSON、不需要理解 DID。**拖进去，看到结果，就够了。**

### 2.5 核心理念

```
Alpha-ID = DID（去中心化身份） + Persona（人格画像） + 私钥（你控制）
```

- **DID** — `did:aid:xxx`，W3C 标准去中心化身份
- **Persona** — 从对话数据提取的沟通风格、技术偏好、工作节奏
- **MCP** — 通过 Anthropic MCP 协议注入任何 AI 工具
- **私钥在本地** — 没人能锁你的数据

## 三、七框架思维方法论

> 本文档定义了 Alpha-ID 项目使用的七种核心思维方式。每个参与项目决策的人，都应该先运行这七套框架。

### 3.1 宇宙星链

**核心思想**：你不是在一个二维平面上找位置，你是在一个三维立体空间中感知生态。

传统分析是平面的——A 是竞品、B 是合作伙伴、C 要提防。
宇宙星链是 3D 立体环绕式的——**以我为中心，从四面八方不同程度地向外扩散。**

```
第一层：我为中心 → 向所有方向辐射
第二层：每个辐射点又成为新中心 → 继续向外辐射
第三层：继续...
→ 视角呈指数级倍增
```

#### 七个轨道

| # | 轨道 | 定义 | 当前最强玩家 |
|:-:|:----:|------|:----------:|
| 1 | **通用个人 AI** | 面向最终用户的独立 Agent | Hermes 48k⭐ |
| 2 | **身份层** | 去中心化身份标准与 DID | SOUL Protocol |
| 3 | **记忆层** | Agent 长期记忆存储与检索 | Mem0 $24M |
| 4 | **执行/操作层** | AI 操作电脑界面的能力 | OpenClaw 280k⭐ |
| 5 | **协调/多 Agent 层** | 多个 Agent 之间的工作流编排 | Agent HQ |
| 6 | **社交/A2A 生态层** | Agent 之间的通信协议 | A2A / IETF |
| 7 | **开发者平台** | Agent 构建框架与 SDK | MS/OpenAI/Anthropic |

#### 核心结论

> **Alpha-ID 不在任何一个单轨道上竞争。它在所有轨道的交叉点上——每一个轨道上的最强玩家都缺一个"人的身份层"。**

### 3.2 第一性原理

**核心思想**：第一性原理 = 不断地压缩，再压缩，直到事物的本质到底从哪里出发。

传统思维问："别人怎么做？我跟着优化哪里？"
第一性原理问："**把这件事压缩到不可再压缩，最底层的那个点是什么？**"

#### 四步法

1. **识别假设**：把你对当前问题的所有"默认认知"列出来
2. **拆到不可再分**：问每一个假设："这是事实，还是只是现状？"
3. **从零重建**：去掉所有"现状"假设，只保留不可再分的事实，重新设计解决方案
4. **对比重建方案与当前方案**：知道自己哪些是主动选择的，哪些是在默认接受

**关键补充**：光压缩是不够的。找到了本质不等于解决了问题。真正的第一性原理包含两个动作：
1. **压缩**：把问题拆到不可再分
2. **重建**：从不可再分的原点，重新搭建解决方案

### 3.3 反向推翻

**核心思想**：顶级科学家观测到一个现象，但不敢确认、不敢承认。这时他们不会直接证明它是对的——他们会全力证明它是错的。如果所有证明它是错的尝试都失败了，假设就成立了。

传统决策思维问："这个方向为什么能行？"
反向推翻思维问："**这个方向在什么条件下一定会失败？**"

#### 五步法

1. **陈述假设**：写下你要验证的方向，用一句话
2. **主动找反例**：全力找"这会在什么情况下彻底失败"
3. **评估反例的致命程度**：概率 × 致命程度
4. **只有通过了反推的假设，才值得执行**：至少找到三个能站得住的反例
5. **证伪成本排序**：优先验证"致命程度高 + 发生概率高"的反例

### 3.4 递归降维

**核心思想**：复杂问题不是一次性解决的。把它降一层——如果还复杂，再降一层。直到降到你认知范围内可以处理的程度，处理完再一层层升回去。

传统思维："这个问题太复杂了，需要全面方案。"
递归降维思维："**这个问题的上一层是什么？上一层解决后，当前层是不是自然解决了？**"

#### 三步法

1. **识别当前维度**：战略层 / 战术层 / 执行层
2. **降维**：问自己"这个问题在更低的维度上有没有一个版本是可以先解决的？"
3. **升维验证**：降维解决后，升回去检查这个低维的解法在高维上还成立吗

### 3.5 反脆弱设计

**核心思想**：不是所有东西都应该追求"稳定"。有些东西需要在波动中变强。

传统设计问："怎么让系统稳定不出错？"
反脆弱设计问："**怎么让系统在出错后变得更强？**"

#### 三个层次

| 层次 | 定义 | 例子 |
|:----|:----|:----|
| **脆弱** | 经不起波动，一碰就碎 | 依赖单一 API Key 的工具 |
| **坚韧** | 能承受波动，不受影响 | 有 fallback 的工具 |
| **反脆弱** | 从波动中获益，越挫越强 | 每次失败自动补一条规则的工具 |

#### 在项目中的应用

1. **不是防止失败，而是设计"有益的失败路径"**：每一次"工具连不上"不是 bug，是 AID 学习"这个工具什么时候会断"的机会
2. **多路径依赖**：不要只依赖一种方式获取信息，设计三条路径
3. **用户越多系统越强**：用户越多，记忆模式识别越准，冷启动越快

> **反脆弱不是"不怕失败"。是"失败一次，聪明一分"。**

### 3.6 节律控制

**核心思想**：每一次扩散（吸收新信息/新方向/新反馈）之后，必须跟上一次收缩（输出可执行方案）。像呼吸一样交替进行。

| 状态 | 表现 | 下一步 |
|:----|:----|:------|
| **过度扩散** | 一直在收集、分析、讨论，没有输出 | 进入收缩模式：锁定范围、输出方案 |
| **过度收缩** | 一直在执行，没有新输入 | 进入扩散模式：吸收新信息、审视方向 |
| **平衡** | 扩散→收缩→扩散→收缩 交替进行 | 继续保持 |

### 3.7 全息追溯

**核心思想**：任何结论、任何数据点、任何决策，都必须能在 3 步以内追溯到它的原始证据。

传统思维问："这个结论对吗？"
全息追溯问："**支撑这个结论的每一环证据链，我能随时拉出来看吗？**"

#### 三层追溯

| 层级 | 追溯内容 | 例子 |
|------|---------|------|
| **第一层：来源** | 这个结论从哪里来？ | "我从 chatgpt 采集器的 2026-06-05 对话中提取了这个偏好" |
| **第二层：推理链** | 从原始数据到最终结论经过了哪些步骤？ | "用户在 17 次对话中提到 Rust 相关关键词 → 统计频次 → 归纳为技术偏好" |
| **第三层：反向验证** | 如果拿掉这个证据，结论还成立吗？ | "移除最活跃的 3 次对话后，Rust 偏好从强降为弱 → 结论对样本敏感" |

> **不做"相信我"——做"看证据，自己判断"。**

### 3.8 七套框架联动

```
宇宙星链（告诉我"生态坐标"）
      ↓
第一性原理（告诉我"本质是什么"）
      ↓
反向推翻（告诉我"为什么不会死"）
      ↓
递归降维（告诉我"先从哪一层下手"）
      ↓
反脆弱设计（告诉我"怎么越用越强"）
      ↓
节律控制（告诉我"现在该扩散还是收缩"）
      ↓
全息追溯（告诉我"每一步的证据链完整吗"）
      ↓
通过 → 执行
不通过 → 回到宇宙星链重新定位
```

### 4.2 十条核心决策

> **优先级声明原则**：
> - ✅ **核心定位**：必须做
> - ⏸ **当前聚焦**：当前阶段先做，其他方向暂缓
> - 🚫 **永久原则**：永远不碰的红线
> - ⚠️ **条件约束**：特定条件下适用

| # | 结论 | 优先级 | 触发条件（什么时候重新评估） |
|:-:|:-----|:------:|:------------------------|
| 1 | **核心定位：把散落的你捡起来** — 收集、重组、延续数字世界里的碎片 | ✅ 核心定位 | — |
| 2 | **当前阶段聚焦核心能力** — 先做好采集、重组、展示 | ⏸ 当前聚焦 | 核心价值验证完成 |
| 3 | **不做模型开发** — 换模型时 Alpha-ID 不换 | ⏸ 当前聚焦 | 出现比 LLM 更核心的推理能力 |
| 4 | **不做框架/SDK** — 面向最终用户 | ⏸ 当前聚焦 | 出现企业级接入需求 |
| 5 | **不做平台** — 寄生策略更轻 | ⏸ 当前聚焦 | 寄生策略无法持续获取用户 |
| 6 | **不造协议** — 搭便车：MCP + A2A | ⏸ 当前聚焦 | 行业标准缺失或不适用 |
| 7 | **DID 对用户无意义** — 藏在体验下面 | 🚫 永久原则 | — |
| 8 | **私钥永远在客户端** — 大脑只验证不签名 | 🚫 永久原则 | — |
| 9 | **core/ 零外部依赖** — 依赖向内 | 🚫 永久原则 | — |
| 10 | **I2I + A2A 两者都要** — I2I 是关系骨架，A2A 是行动血肉 | ✅ 核心定位 | — |

### 4.3 锁定策略

| 方向 | 策略 |
|------|------|
| 冷启动 | 导入已有数字痕迹 + 本机信号扫描 |
| 导入器顺序 | ChatGPT → Claude → GitHub → 浏览器 |
| 魔法时刻 | 导入后回到原工具 → 发现 Agent 已认识自己 |
| 推广 | 推现象不推产品 |
| 商业模式 | AID 存在 = 永远免费 |
| Computer Use | 像人一样看屏幕+操作，不写平台 API |

### 4.4 Ghost Layer 与双大脑

| 维度 | 定位 |
|------|------|
| 本质 | 坐在所有 AI 工具之上的幽灵层 |
| 做什么 | 不造新 AI，让已有 AI 认识你 |
| 对用户价值 | 你打开任何 AI，它都认得你 |
| 存在方式 | 后台工作，用户几乎不主动打开 |

| 大脑 | 职责 |
|------|------|
| **内在大脑** | DID + Profile 画像 → 定义"你是谁"——不变的身份锚点 |
| **外在大脑** | 三层记忆 + 因果图谱 + 关系图谱 → 记录经历、决策、关系 |

**I2I + A2A**：没有 A2A，关系是空架子。没有 I2I，Agent 协作不知道替谁干活。两者缺一不可。

### 4.5 五个底层错误的应对

| # | 错误 | Alpha-ID 应对 |
|:-:|------|-------------|
| 1 | AI Agent 无"自我" | DID + 本地私钥 |
| 2 | MCP/A2A 没解决"谁在调用" | MCP 身份层注入 |
| 3 | LLM 推理是伪因果 | 因果图谱 + 七框架约束 |
| 4 | Agent 安全是事后补丁 | PoE 执行证明 + DID 签名审计链 |
| 5 | 个人 AI 都是中心化黑盒 | 本地优先 + 私钥自持 |

### 4.6 语音交互方向

| 方向 | 做什么 | 阶段 |
|:-----|:-------|:-----|
| 语音输入（ASR） | 语音→文字→进入记忆系统 | Phase 1 |
| 语音输出（TTS） | Alpha-ID 通过语音回答、提醒、播报 | Phase 1 |
| 声线人格化 | 让 Alpha-ID 说话像用户 | Phase 2 |
| 唤醒词 | 用唤醒词激活 Alpha-ID | Phase 2 |

**技术路线**：ASR/TTS 用系统原生 API，不追求完美，先跑通通路。

## 六、四阶段路线图

### Phase 0 — 画像骨架 ✅ 已完成

```
├── DID 存在 + Profile 有内容
├── 单一数据源跑通 collect → extract → show
├── 完成标志（技术）：`aid init && aid collect chatgpt <zip> && aid profile show`
```
