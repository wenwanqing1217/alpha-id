# Alpha-ID 项目介绍

> 把散落在数字世界里的你捡起来——收集、重组、延续，让它替你活着、替你社交、替你学习。

## 一句话定义

> **Alpha-ID 不是另一个 AI 助手，而是坐在所有 AI 工具之上的 Ghost Layer（幽灵层）：换模型、换平台、换设备，Alpha-ID 不换。**

一个数字身份，所有 AI 工具都认识同一个你。

### 面试可直接讲

**一句话**：不是另一个 AI 助理，是坐在所有 AI 工具之上的 Ghost Layer。先看本机有什么，再决定采集什么；换工具、换平台，Alpha-ID 不换。

**三句话叙事**：
1. 大多数项目做“新增一个助手”；Alpha-ID 做“让所有工具都认识同一个你”。
2. 核心不是云记忆，而是本地 DID + 本机痕迹 + MCP 身份注入。
3. 私钥在本地，画像可导出，用户拥有数字身份主权。

**它解决的核心问题**：你在 ChatGPT、Claude、Cursor、浏览器里的记忆和身份都是孤岛；Alpha-ID 用本地 DID + 本机痕迹挖掘 + MCP 注入，让所有工具共享同一个你。

## 它解决的核心问题

| 场景 | 没有 Alpha-ID | 有 Alpha-ID |
|:-----|:--------------|:------------|
| 换 AI 工具 | 每次都重新自我介绍 | 身份、风格、记忆自动跟着走 |
| 跨平台工作 | ChatGPT 不认识 Claude 历史 | 一个 `did:aid:` 贯穿所有工具 |
| 本机痕迹 | 分散在代码、聊天、浏览器里 | 统一成可解释的人格画像 |
| 数据主权 | 记忆锁在平台服务器 | 私钥在本地，记忆可导出 |
| 面试/展示 | 只有零散功能 demo | 有完整系统叙事和魔法时刻 |

**核心判断**：现在最稀缺的不是“又一个 AI 助理”，而是“属于用户的跨工具连续性层”。

## 核心设计理念

**产品定位**：把散落在数字世界里的你捡起来——收集、重组、延续，让它替你活着、替你社交、替你学习。

**五项永久红线**：
1. **私钥永远在客户端**，不上传、不共享。
2. **DID 对用户无意义**，藏在体验下面（用户不说“我的 DID”，说“它认识我”）。
3. **I2I + A2A 两者都要**：I2I（Identity to Identity）是关系骨架，A2A（Agent to Agent）是行动血肉。
4. **core/ 零外部依赖**：核心逻辑不依赖任何外部框架，保持稳定。
5. **不做模型、不做平台、不造协议**：聚焦核心能力，搭便车（MCP + A2A）。

**设计原则**：
- 用户感受效果，不感受技术
- 先做可演示的完整链路，不做最小 demo
- 700 行闭环比 1500 行半成品强
- Graceful degradation：没 API key、没 GPU、没网络也能工作

## 技术架构概览

### 系统定位：Ghost Layer

```
┌──────────────────────────────────────┐
│              用户客户端                │
│  身份 | 隐私 | 记忆 | 社交 | 安全      │
│  私钥永远在客户端                      │
└──────────────────┬───────────────────┘
                    │ API / MCP
┌──────────────────┴───────────────────┐
│           TwinBrain（大脑）            │
│  记忆整理 | 社交行为 | 状态管理        │
│  只能响应/执行 | 不能伪造身份          │
└──────────────────┬───────────────────┘
                    │
┌──────────────────┴───────────────────┐
│              存储层                    │
│   结构化数据 | 向量记忆                 │
└──────────────────────────────────────┘
```

核心原则：私钥在客户端 | 记忆是用户资产核心

### 双大脑架构

| 大脑 | 职责 |
|:-----|:-----|
| **内在大脑** | DID + Profile 画像 → 定义"你是谁"——不变的身份锚点 |
| **外在大脑** | 三层记忆 + 因果图谱 + 关系图谱 → 记录经历、决策、关系 |

**I2I + A2A**：没有 A2A，关系是空架子。没有 I2I，Agent 协作不知道替谁干活。两者缺一不可。

### 外置大脑三层架构

```
┌──────────────────────────────────────┐
│  第三层：大模型适配层                   │
│  身份设定 + 框架约束 + 表达风格 + 记忆注入 │
├──────────────────────────────────────┤
│  第二层：思维框架引擎（核心壁垒）        │
│  宇宙星链→第一性原理→反向推翻           │
│  →递归降维→反脆弱→节律控制→全息追溯     │
├──────────────────────────────────────┤
│  第一层：用户画像大脑                   │
│  DID + 画像 + 三层记忆 + 因果图谱       │
└──────────────────────────────────────┘
```

**五个底层错误的应对**：
1. AI Agent 无"自我" → DID + 本地私钥
2. MCP/A2A 没解决"谁在调用" → MCP 身份层注入
3. LLM 推理是伪因果 → 因果图谱 + 七框架约束
4. Agent 安全是事后补丁 → PoE 执行证明 + DID 签名审计链
5. 个人 AI 都是中心化黑盒 → 本地优先 + 私钥自持

**核心原则**：每次纠结"要不要加这个功能"，问——**它让 AI 更懂"为什么我这么想"了吗？** 是就加，不是就删。

### 技术栈

- **语言**：Python 3.12+
- **CLI**：Typer（入口命令 `aid`）
- **Web/API**：FastAPI
- **协议**：MCP（Model Context Protocol）+ A2A（Agent to Agent）
- **身份**：本地 Ed25519，DID 方法 `did:aid:`
- **测试**：pytest，800+ 测试用例
- **代码质量**：ruff lint/format + pyright 类型检查

### 代码结构

```
projects/
  src/
    alpha_id/       CLI、采集器、Web、MCP server
    core/           零外部依赖核心：DID、记忆、双大脑、关系/风险
    api/            FastAPI 路由
    auth/           JWT auth
    tools/          桌面自动化工具
    entrypoints/    统一入口：CLI / MCP / API / Daemon
  docs/            核心文档与落地方案
  tests/           自动化测试
```

## 当前可演示的完整链路（Phase 1）

```
aid init
→ aid profile mine --path .
→ aid profile show
→ aid profile web
→ aid-mcp
```

**魔法时刻**：用户运行 `aid profile mine --path .` 后，看到的不只是一张卡片。系统先扫描了他电脑里**实际存在**的痕迹，再按这些痕迹认出他。不会先假设他一定有 ChatGPT / Claude / Cursor，而是先看他**有什么**。

这个瞬间解释了项目到底在做一种什么新东西：**不是工具，是数字存在。**

## 为什么它不一样（差异化）

| 维度 | 传统 AI 助手/记忆工具 | Alpha-ID |
|:-----|:----------------------|:---------|
| 身份 | 平台绑定 | 本地 DID，跨平台可移植 |
| 记忆 | 云存储，平台锁定 | 本地优先，用户主权 |
| 多工具 | 每个工具独立 | Ghost Layer 统一身份层 |
| 协议 | 自己造轮子 | 搭便车 MCP + A2A |
| 隐私 | 数据在服务器 | 私钥永不上传 |
| 定位 | 新增一个助手 | 让已有工具都认识你 |
