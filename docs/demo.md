   - `aid init` 生成本地 DID，私钥不离开本机。

   - `python scripts/demo.py` 让 MCP 客户端读取 `profile://identity`。
4. **壁垒**：用户的数字历史关系不可复制，本地优先 + 私钥自持不可复制。

## 面试官追问速查

### 1. 你和其他 AI 助理 / AI 工作流项目最大的区别是什么？

**答**：大多数项目是“给用户新增一个助手”或“把单一平台串起来”。Alpha-ID 的目标是成为**用户的数字身份基础设施**：不是再做一个工具，而是让所有现有工具都认识同一个你。它的核心差异是 DID + 本地主权 + 本机痕迹优先，而不是云端记忆。

### 2. 为什么 DID 重要？为什么不能只做一个用户画像文件？

**答**：因为画像文件没有“身份连续性”。DID 解决的是“你是谁、你是谁的工具、谁能代表你说话”的问题。没有 DID，画像只是一个静态简历；有了 DID，画像才能被 MCP / A2A / 代理网络安全地调用和继承。

### 3. 你们到底是在做模型、平台还是协议？

**答**：当前阶段都不做。我们做的是**记忆与身份层**：先围绕用户本机痕迹完成可演示闭环，再把能力通过 MCP 注入现有工具。模型、平台、协议都是远期生态位，不是当前交付物。

### 4. 商业价值到底在哪里？

**答**：短期是开源影响力 + 高端岗位可信度 + 本地主权 AI 顾问方案；中期是重度 AI 用户的订阅服务：记忆备份、同步、高级分析；长期是 A2A / Agent 生态里的“可信身份 + 记忆”标准层。核心逻辑是：**谁先定义用户数字存在的标准，谁就占据下一代 AI 基础设施位。**

### 5. 现在这个项目能证明什么？

**答**：能证明三件事：第一，我能从零设计并落地一个完整系统，而不只是功能模块；第二，我会把“用户主权”和“可解释性”放在第一位；第三，我能把技术叙事转化为面试/商业叙事，让技术价值被非技术听众快速理解。
