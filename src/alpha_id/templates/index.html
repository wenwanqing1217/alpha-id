01 / VISION

为什么需要数字灵魂？

AI 工具在爆发式增长，但"你"正变得越来越分散。每换一个工具，就要重新介绍一次自己。

旧世界 BEFORE

碎片化的你

—
身份碎片化：ChatGPT 的你 ≠ Claude 的你 ≠ Cursor 的你
—
记忆孤岛：每个工具都有自己的上下文窗口，无法跨工具迁移
—
决策断层：因果链无法被 AI 理解，建议缺乏个性化与连续性
—
数据主权：你生成的数据属于平台，无法自由迁移，隐私难以保障
—
协作困难：团队知识分散在多人对话中，新人无法继承上下文
—
协议割裂：MCP、A2A、浏览器扩展各成体系，没有统一身份层
问题公式
N 个工具 · N 个"你" = O(N²) 的上下文冗余

统一的数字灵魂

+
一个身份走遍所有平台：DID + Ed25519 签名，你是你，不是平台分配的用户 ID
+
无感注入：打开任何 AI 工具自动认出你，记忆跨工具迁移，不再重新自我介绍
+
代替操作：不只是聊天，真正代替你操作电脑——看屏幕、点按钮、处理文件
+
私钥在你手里：本地优先 + 端到端加密 + 社交恢复，身份不会被封禁
+
A2A 社交：你的数字灵魂与其他人的数字灵魂交朋友、协作。Agent-to-Agent
+
PoE 可验证：每条操作生成哈希链，全程可审计、可追溯

EDGE · LAYER

线层 · 10 种定义"关系"的边

节点之间的边定义了因果、归属、调用、时序、验证等关系。没有边，节点只是散落的星尘。

10 EDGES
因果边 CAUSAL · strength 0.0~1.0
目标节点 → 动作节点 → 结果节点 → 反馈节点。强度来源：用户手动确认 = 1.0 / LLM 初始 = 0.6 / 行为序列验证 += 0.1。
反脆弱：strength < 0.3 且 90 天未使用时，系统建议确认或删除。
归属边 OWNERSHIP · DID → 原子点
将所有原子点锚定到一个 DID，确立"这是谁的数据"。是数据主权的基石。
反脆弱：即使 DID 被注销，归属边的历史记录仍保留在只读审计表中。
调用边 CALL · Skill → Skill · sync/async
一个 Skill 执行过程中调用另一个 Skill，可能跨进程、跨语言。形成能力依赖图。
反脆弱：被调用方失败时自动重试（指数退避），并提供降级路径。
事件触发边 TRIGGER · Event → Skill
当特定系统事件发生时自动触发某个 Skill。例如"剪贴板内容变化 → 若匹配 URL → 保存"。
属性：priority / filter 条件 / cooldown 防抖。
通信边 COMM · MCP / A2A · 双向
MCP 请求-响应或 A2A 消息交换。对外连接你的数字灵魂与外部世界。
反脆弱：MCP 失败自动降级为剪贴板注入模式。
存储边 STORAGE · 原子点 → SQLite 行
表示原子点在持久层的物理位置。用于全息追溯——知道一个节点存在哪张表的哪一行。
验证边 VERIFY · PoE → Skill 执行
PoE 条目验证 Skill 执行记录，形成哈希链。每条 PoE 包含 previous_poe_hash，确保全程可追溯。
反脆弱：哈希链断裂时标记为"不可信"，但不影响其他 PoE。
展示边 DISPLAY · 状态 → UI
内部状态变化触发 UI 更新（悬浮球、Web 星链）。通过 WebSocket 推送事件。
依赖边 DEPEND · 面 → 面 · hard/soft
一个能力域依赖另一个域的能力。hard = 必须存在；soft = 可选降级。
示例：决策面 依赖 图谱引擎面（hard）；展示面 依赖 桥接面（soft）。
时序边 TEMPORAL · 先 → 后 · 非因果
仅表示时间先后顺序，不蕴含因果关系。用于时间线可视化、行为模式分析。

03 / FRAMEWORK

六套战略思维框架

每次战略决策前运行的六套思维工具：宇宙星链、第一性原理、反向推翻、递归降维、反脆弱设计、节律控制。

宇宙星链
STARLINK
以我为中心，从四面八方不同程度向外辐射。每个辐射点又成为新中心，视角呈指数级倍增。
七轨道：通用AI / 身份层 / 记忆层 / 执行层 / 协调层 / 社交层 / 平台层
第一性原理
FIRST PRINCIPLES
不断压缩到不可再分，找到本质后重新组装。区分"事实"与"现状"，从零重建方案。
四步法：识别假设 → 拆到不可分 → 从零重建 → 对比方案
反向推翻
REVERSE VERIFY
全力证明方向是错的。如果所有证明失败的尝试都失败了，假设才成立。
五步法：陈述假设 → 找反例 → 评估致命度 → 对策 → 执行
递归降维
RECURSIVE
复杂问题降一层，还复杂再降一层。直到降到可处理的程度，处理完再升回去。
三步法：识别维度 → 降维执行 → 升维验证
反脆弱设计
ANTI-FRAGILE
不是防止失败，而是设计有益的失败路径。每次失败自动补一条规则，系统越来越聪明。
三层：脆弱 → 坚韧 → 反脆弱
节律控制
RHYTHM
每次扩散（吸收新信息）后必须跟上收缩（输出方案）。像呼吸一样交替。
状态：过度扩散 → 过度收缩 → 平衡
